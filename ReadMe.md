# 域外法查明与深度研判智能工作台 (OverseasLawAssist)
## 用户操作手册与功能全景指南

---

### 一、 系统定位与核心价值

在跨国商事诉讼、涉外仲裁及出海合规业务中，法律专业人员往往面临多重实务困境：域外法成文法典条文庞杂、语言壁垒森严、判例规则演进繁复、通用大语言模型存在严重的法律条文虚构（幻觉）与论证逻辑跳跃。

**OverseasLawAssist（域外法查明与深度研判智能工作台）** 是专为涉外商事法官、涉外仲裁员、涉外争议解决律师及跨国企业法务团队研发的专业级法律科技工作台。系统依托 **LangGraph 确定性状态图流转**、**受约束双通道 Agentic RAG（检索增强生成）**、**Multi-Agent 异构双模型博弈** 与 **法律知识本体图谱**，提供覆盖“准据法识别 ➔ 争点拆解 ➔ 精准条文检索 ➔ 要件事实四态涵摄 ➔ 动态胜败边界推演 ➔ 对方红队致命抗辩反制 ➔ 证据链闭环图谱 ➔ 法庭级双语查明报告导出”的端到端全流程深度研判能力。

系统严格贯彻**司法中立防线（V8 Anti-Predictive Guardrail）**，彻底摈弃“胜诉率 85%”等误导性伪量化概率，创新采用**假定条件推演矩阵（Condition Precedent If-Then Matrix）**，为涉外法律实务提供严谨、可检验、可溯源的办案决策支持。

### 二、 支持法域与权威数据底座

系统底层采用法域与语言解耦架构，目前已实现对两大世界主要法域体系的深度支持：

#### 1. 德国联邦法域 (German Federal Law / `de_federal`)
* **成文法典库 (Norms)**：官方标准结构化入库 **4,574** 条现行有效联邦法条，精确解析至“条 (Paragraph/Artikel)”、“款 (Absatz)”、“项 (Nummer)”，涵盖：
  * 《德国民法典》(Bürgerliches Gesetzbuch, BGB) 2,551 条
  * 《德国民事诉讼法》(Zivilprozessordnung, ZPO) 1,094 条
  * 《德国商法典》(Handelsgesetzbuch, HGB) 696 条
  * 《德国有限责任公司法》(GmbH-Gesetz, GmbHG) 127 条
  * 《德国民法施行法/国际私法》(EGBGB) 101 条
  * 欧盟《罗马条例 I》(Rome I Regulation) 5 条
* **权威判例库 (Cases)**：深度收录德意志联邦最高法院 (Bundesgerichtshof, BGH) 涉外买卖、公司纠纷等金标准生效裁判文书，构建法条-先例引用关联拓扑网络。
* **重大法典现代化修订时点库**：内建 2002 年债法现代化法案、2022 年买卖法与数字内容新规等关键法律变动时点，杜绝引用已失效或已变更条文。

#### 2. 美国商事与联邦法域 (US Commercial Law / `us_commercial`)
* **核心成文法规范库 (Norms 68 条，全局法条达 4,642 条)**：
  * 《美国统一商法典》(UCC 49 条)：重点覆盖 Article 2 买卖篇全链条（合同成立通则 § 2-204、书面要件 § 2-201、要约与承诺 § 2-206、格式之战 § 2-207、合同变更免除对价 § 2-209、明示/默示适销性担保 § 2-313/§ 2-314、免责声明 § 2-316、补正权 § 2-508、风险转移 § 2-509、完美履行 § 2-601、合理期限异议通知 § 2-607、不安抗辩与充分保证 § 2-609、商业不能免责 § 2-615、替代采购Cover § 2-712、利润损失与可预见性损害赔偿 § 2-714/§ 2-715、诉讼时效 § 2-725）及 Article 1 总则商业惯例与诚实信用通则；
  * 《特拉华州通用公司法》(DGCL 7 条)：覆盖公司章程董事免责 102(b)(7)、董事会权力与商业判断规则 BJR § 141、利益冲突安全港 § 144、股权转让限制 § 202、股东查账权 § 220、公司合并 § 251 与重大资产出售 § 271；
  * 《美国法典》(U.S.C. 12 条)：覆盖 9 U.S.C. 联邦仲裁法 (FAA) 涉外仲裁协议强制执行、纽约公约在美直接适用与撤销裁决法定事由（§ 1-§ 10, § 201），以及 28 U.S.C. § 1782 跨境司法协助取证与外国主权豁免。
* **联邦法院与州最高法院金标准判例库 (Cases 27 篇，含 15 篇全美代表性先例)**：
  * 本地精选收录联邦最高法院 (SCOTUS)、第二/三/五/七巡回上诉法院 (Cir.)、特拉华州最高法院权威商事判例（涵盖 Eastern Air Lines v. McDonnell Douglas, Step-Saver v. Wyse, Delano Growers, Intel v. AMD, ZF Automotive, Unocal v. Mesa, Delchi Carrier v. Rotorex, Hall Street v. Mattel, Mitsubishi Motors v. Soler, First Options v. Kaplan, MFW 框架 Kahn v. M&F Worldwide, AMF v. McDonald's, ProCD v. Zeidenberg 等）；
  * 构建**成文法-判例双向拓扑图谱**：119 条拓扑边 (edges) 与 47 条高频法条-判例物化索引 (hot_norm_cases)，检索成文法时毫秒级自动带出经典判例；
  * 支持**轻量安全滚雪球扩充机制 (`scripts/snowball_expand_cases.py`)**：前置结合 **Shepardizing / KeyCite 先验有效性门禁**，自动拦截推翻失效的“坏法”（如已被全美巡回区一致推翻的 Roto-Lith 格式之战旧案）与未公开发表的备忘录，验证通过后一键安全落盘、自动重构分块与 BM25 词法索引。
* **先例效力验真机制 (Shepardizing / KeyCite Verification)**：
  * 实时标注先例司法存续状态：`Good Law`（良好先例）、`Distinguished`（案情区分）、`Overruled`（已被推翻）或 `Questioned`（存疑），确保法源引用权威可靠。

### 三、 核心功能矩阵与界面呈现内容

工作台界面分为左侧导航与控制台、顶部全景战略决策看板、中央 Agent 流水线与深度研判卡片，呈现以下八大专业功能模块：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 顶部：全景案件总结与四大战略支柱看板 (Executive Summary & Strategic Radar)  │
├──────────────────────┬──────────────────────────────────────────────────────┤
│ 左侧导航与控制台     │ 中央主体工作区                                       │
│                      │ ┌──────────────────────────────────────────────────┐ │
│ 1. 案件录入与基本信息│ │ 模块 A：7 大专业 Agent 协同流水线执行追踪        │ │
│ 2. 案情深度分析看板  │ ├──────────────────────────────────────────────────┤ │
│ 3. 证据链闭环图谱    │ │ 模块 B：动态胜败边界推演与心证分水岭             │ │
│ 4. 域外法律检索库    │ ├──────────────────────────────────────────────────┤ │
│ 5. 当事人材料核验    │ │ 模块 C：红队攻防对抗手册（对方致命抗辩反制盾牌） │ │
│ 6. 双语查明意见书    │ ├──────────────────────────────────────────────────┤ │
│ 7. Copilot 追问研判  │ │ 模块 D：构成要件四态严密涵摄与事实闭环           │ │
│                      │ └──────────────────────────────────────────────────┘ │
└──────────────────────┴──────────────────────────────────────────────────────┘
```

#### 1. 全景案件总结与四大战略支柱看板 (Executive Summary)
位于案件分析主页顶层，采用深色机构级简报设计，汇聚审判与出庭核心研判全貌：
* **战略决策顶栏**：
  * 准据法识别标签与法域体系徽章；
  * CISG 公约排他性状态判定标签；
  * 构成要件总体完备率进度（已满足/部分满足/欠缺）；
  * 核心请求权基础法条群（如 BGB § 437, § 434）。
* **四大战略支柱看板 (Four Strategic Pillars)**：
  * **动态胜败边界推演 (Outcome Bounds)**：提炼乐观主张成立条件、诉讼下行基准防线与僵局突破路径，直观展示审理心证走向；
  * **红队首要抗辩预测 (Red Team D1)**：精准标注对方资深诉讼律师首要出击的致命抗辩点（如检验失权、合理期限争议）；
  * **构成要件状态穿透 (Element Status)**：按红绿黄蓝四色灯直观指示各项法条要件证明力现状；
  * **关键补证行动清单 (Key Evidence Actions)**：列出影响判决胜败走向的急需补充证据事项。
* **看板一键定位详情 (Cross-Section Quick Jump)**：点击任意看板卡片，界面自动平滑滚动至对应的深度研判分析区域。

#### 2. 7 大专业 Multi-Agent 协同工作台 (Specialized Multi-Agent Collaboration)
系统由 7 个专职智能体分工协作，基于状态图流水线运行，界面完整呈现各 Agent 的执行状态、响应耗时与研判日志：
1. **事实要素抽取 Agent (Extractor)**：结构化解析非结构化案情陈述，剥离原被告主体、法律行为、涉案标的物、履约时序及核心事实片断（F1, F2, F3...）；
2. **准据法与时点前检 Agent (Precheck)**：核验国际私法选法条款有效性、自动探测 CISG 触发条件、核查法典重大修订时点；
3. **争点与举证责任拆解 Agent (Decomposer)**：将案件拆解为实体法争点、程序法争点与事实查明焦点，明确双方举证分配；
4. **双通道智能检索 Agent (Researcher)**：结合德语形态学复合词切分、BM25 词法检索、BGE-M3 语义向量检索与法典知识图谱，精准命中成文规范与判例；
5. **要件事实三段论匹配 Agent (Matcher)**：执行三段论严格比对，对各争点法定要件标注 `satisfied` / `partial` / `missing` / `disputed`；
6. **策略推演与红队模拟 Agent (Strategist & Red Team)**：构建假定条件推演矩阵，扮演对方资深出庭律师实施红蓝对抗，生成反制盾牌；
7. **双语起草与独立裁判 Agent (Drafter & Critic)**：调用独立异构大模型执行 V1-V11 质量门禁审查，起草符合司法查明规范的中外双语法律意见书。

#### 3. 动态胜败边界推演与心证分水岭 (Case Strategic Assessment)
* **法官心证分水岭判定 (Judicial Tipping Point)**：
  * 提炼决定法官自由心证向原告或被告倾斜的实质性裁量分水岭（例如：“到港开箱后 2 日内发出异议是否满足商事即刻检验义务通知”）；
  * 标注影响裁判心证的关键事实依据与对应证据支撑。
* **假定条件推演矩阵 (Outcome Branches - If-Then)**：
  * **乐观假定分支 (Optimistic)**：若法院认定某项关键事实成立，原告可全额支持解约及退款请求；
  * **基准稳健分支 (Pessimistic / Base)**：若出现不利事实认定，原告退保的最低实体权利边界及备位请求权；
  * **突破路径分支 (Breakthrough)**：针对争议焦点提出的特殊抗辩突破点（例如：主张对方明知瑕疵而恶意隐瞒，从而豁免检验义务）。
* **可交互关键补证清单**：
  * 提供支持现场勾选复核的补充证据待办事项；
  * 明确标注补证目标要件、证据类型及举证期限要求。

#### 4. 红队攻防对抗手册 (Red Team Defense Playbook)
* **对方首选致命抗辩预测 (D1, D2...)**：
  * 深度模拟对方大律师可能采取的程序抗辩（管辖权异议、当事人不适格）与实体抗辩（除斥期间届满、自认、检验失权、不可抗力）；
  * 标注该抗辩适用的法条依据（如 HGB § 377 或 UCC § 2-607(3)(a)）。
* **我方防御反制盾牌 (Counter Defense)**：
  * 提供针对性的法理反驳逻辑、阻却事由与判例支撑；
  * 指引必须补充的阻却证据材料（如催告邮件发送回执、技术交接纪要）。

#### 5. 审判证据链闭环图谱与事实溯源 (Evidence Traceability Graph)
* **双模呈现方式**：支持交互式 Mermaid 图谱与结构化表格视图一键切换；
* **四级闭环链条**：完整串联 `M# 原始证据材料` ➔ `F# 事实陈述片断` ➔ `EL# 法定构成要件` ➔ `§ 规范条文依据`；
* **事实溯源定位**：清晰标注各项认定是否有客观书证、电子数据或勘验笔录支持，直接揪出无证据佐证的孤证推论。

#### 6. 构成要件四态严密涵摄分析看板
* 对各请求权构成要件展示四态指示灯：
  * `已满足 (satisfied)`：证据确凿，事实完全覆盖法条法定要件；
  * `部分满足 (partial)`：具备初步事实，但证明标准尚未达到高度盖然性；
  * `欠缺 (missing)`：完全缺失关键事实或必要证据，存在败诉风险；
  * `争议 (disputed)`：双方各执一词，存在严重举证对抗。
* 提供针对缺失要件与争议要件的法律补强指引。

#### 7. 域外法律检索库与好法验真 (Legal Search & Knowledge Base)
* 支持德国五大法典及美国 UCC、合同法重述的条目级检索；
* 支持成文法典章节树状导航与关联判例穿透；
* 标注判例存续效力标签，防止检索并误用已被废止的失效先例。

#### 8. 双语查明材料包与法庭级 DOCX 报告导出
* 严格按照涉外民事诉讼域外法查明规范生成两套独立材料：
  * **Part A：法庭查明材料包**（中外双语对照，包括准据法条文全本、立法背景、中立权威判例摘录，专供呈递法院合议庭）；
  * **Part B：委托人咨询研判包**（包含商业诉讼策略、红队攻防推演、诉讼方案权衡，供委托人内部决策）。
* 支持一键导出符合专业排版规范的 Microsoft Word (`.docx`) 报告文档。

#### 9. Copilot 追问研判与红方大律师反击演练
* 支持在案件上下文环境中展开多轮连续法律追问；
* 提供“审判法官视角”、“出庭辩护视角”、“公共秩序视角”三种研判模式切换；
* 支持将追问推演出的关键新结论一键反哺至案件基础底稿。

### 四、 系统部署与操作指引

#### 1. 运行环境准备
* **操作系统**：Windows 10/11 (x64) 或 Linux (Ubuntu 20.04+)
* **Python 环境**：Python 3.10.x（建议配置独立虚拟环境）
* **Node.js 环境**：Node.js v18.0+ / npm 9.0+
* **GPU 环境（可选）**：NVIDIA GPU（支持 CUDA 加速，用于本地 BGE-M3 密集向量推理；若无 GPU 则自动平滑回退至 CPU）

#### 2. 服务端与前端启动步骤

**步骤一：启动 Python 后端服务**
打开 PowerShell 或终端，进入项目根目录：
```powershell
# 1. 激活虚拟环境（若有）
.\v\Scripts\Activate.ps1

# 2. 设置 DashScope / OpenAI 大模型 API Key
$env:OPENAI_API_KEY="your-api-key-here"

# 3. 启动 FastAPI 核心后端服务
python run.py
```
终端输出 `Uvicorn running on http://127.0.0.1:8000` 即表示后端服务就绪。

**步骤二：启动前端交互控制台**
另起一个终端窗口，进入 `FrontEnd` 目录：
```powershell
cd FrontEnd
npm install      # 初次运行安装依赖
npm run dev
```
终端输出 `Local: http://localhost:5173/`，在浏览器打开该地址即可进入工作台。

#### 3. 从零创建案件并执行研判（标准实操流程）

* **第 1 步：新建案件并选择法域**
  1. 点击左侧导航栏的 **“新建案件 (New Case)”** 按钮；
  2. 输入案件名称（例如：“中德数控机床跨境买卖物之瑕疵解约纠纷案”）；
  3. 选择目标管辖与准据法域（**德国联邦法 de_federal** 或 **美国商事法 us_commercial**）；
  4. 录入案情事实陈述文本、原告诉求（Claims）及随附关键证据材料名称；
  5. 点击 **“创建并启动分析”**。

* **第 2 步：人在回路审核确认把关 (Human-in-the-Loop Verification)**
  系统在执行过程中设有两处关键的人机协同把关点：
  1. **准据法前检确认**：系统自动分析合同选法条款并提示是否触发 CISG。用户可在线确认排除 CISG 或指定补充适用规则，点击 **“确认准据法”**；
  2. **核心争点拆解确认**：系统列出自动拆解的法律争点与事实争点。用户可勾选采纳、微调法条范围或手动新增争点，点击 **“确认争点并开始深度检索”**。

* **第 3 步：查看全景战略雷达与四大支柱看板**
  流水线执行完成后，主界面顶部呈现深色全景研判看板：
  1. 查阅要件满足率与核心法条引用；
  2. 查阅 Outcome Bounds 胜败边界推演；
  3. 查阅 Red Team D1 对方首要抗辩预测；
  4. 查阅关键补证行动清单，点击卡片直接定位至对应详情区域。

* **第 4 步：深入分析动态攻防与要件核验**
  1. 在 **“动态胜败边界推演与心证分水岭”** 中，研读三种 If-Then 条件分支，勾选跟进补证待办项；
  2. 在 **“红队攻防对抗手册”** 中，查阅对方大律师可能发起的抗辩及我方反制盾牌；
  3. 在 **“构成要件四态涵摄”** 与 **“证据链闭环图谱”** 中，核查各要件是否具有充足书证支持。

* **第 5 步：导出法庭双语查明报告**
  1. 切换至左侧 **“双语查明报告”** 菜单；
  2. 预览中德/中美法条对照及权威判例判词；
  3. 点击右上角 **“导出 Word 报告 (.docx)”** 按钮，系统即刻生成符合涉外司法标准的专业报告文档。

### 五、 设计哲学与系统防线说明

1. **客观中立原则 (V8 Guardrail)**：
   本系统服务于专业法律论证，严禁生成任何带有确定性诉讼概率的论断（例如“胜诉概率 90%”）。系统一律采用严格的形式逻辑假定句式（“在法院认定事实 A 成立的前提下，构成法条 B 所定要件；若对方举证证明事实 C，则面临抗辩 D”），确保研判结论经得起法庭对抗检验。
2. **法源验真与防幻觉 (Veracity Assurance)**：
   所有输出法条均源自底层本地 SQLite 官方核验法典库，所有引用的判例均带有权威案号与司法存续状态标记，杜绝大语言模型幻觉编造法条法源。
3. **极简专业交互 (Restrained Professional UI)**：
   界面设计参考顶级机构级桌面专业应用风格，克制使用色彩，以深邃蓝、中性灰为基底，辅以明确含义的功能状态灯，拒绝浮夸繁复的动效干扰。
